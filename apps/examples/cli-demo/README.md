# @vyui/cli-demo

A runnable Vue-Lynx app that consumes `@vyui/kit` **through the `@vyui/cli`** —
the shadcn-style workflow. Unlike the other demos, this app does **not** depend
on `@vyui/kit`: the styled components were *copied into the project* by the CLI
and live under version control:

- `src/components/vyui/*.vue` — the installed components (`Button`, `Accordion`, `Chip`, `Avatar`)
- `src/lib/vyui/**` — the shared support payload (plugin, theme, composables, utils, preset, tokens)
- `vyui.config.json` — the CLI config (alias `@`, `default` style, registry path)

Its only vyui dependency is `@vyui/core`, resolved from its **published package**
(not the workspace source) — exactly what a real consumer ends up with. The `@`
alias maps to this app's own `src/`, the CLI's default prefix.

```sh
pnpm --filter @vyui/cli-demo dev
```

Scan the LAN QR with [Lynx Explorer](https://lynxjs.org/) for an on-device
preview, or open the printed `main.web.bundle` URL for the web preview.

## How the components got here

Run against the **in-repo registry** (`apps/docs/public/r`, generated by
`pnpm gen:registry`). The CLI also accepts `https://vyui.dev/r`; this demo points
at the local copy so it builds offline and always matches the branch.

```sh
# from this directory (apps/examples/cli-demo)

# 1. scaffold vyui.config.json + the shared lib payload
node ../../../packages/cli/dist/index.js init \
  --registry ../../docs/public/r --style default -y --skip-install

# 2. copy components (deps are pulled in transitively — button → avatar)
pnpm vyui:add add button accordion chip -y --skip-install --overwrite
```

`vyui:add` is a package script pointing at the built CLI (`packages/cli/dist`),
so build the CLI first if needed: `pnpm --filter @vyui/cli build`.

## Wiring (done once, by hand)

The CLI copies files and rewrites imports to the `@` alias; the host app wires
them in — see the inline comments in each file:

- **`lynx.config.ts`** — maps `@` to `src/` for the bundler and resolves
  `@vyui/core` from its built package (not the workspace source).
- **`tailwind.config.ts`** — uses the copied `src/lib/vyui/vyui-preset.js` (not a
  kit import) and feeds it the `VYUI_UI_STATES` the same file re-exports, so the
  `ui-*` state variants work without a `@vyui/kit` dependency.
- **`src/index.ts`** — registers `VyUI` from `@/lib/vyui/plugin` and imports
  `@/lib/vyui/style.css` (the design tokens).

Compare with `apps/examples/kit-demo`, which imports the same components straight
from the `@vyui/kit` package instead of copying them in.
