The browser preview that rspeedy prints is genuinely useful, and it is also the target where Lynx behaves least like itself. Gestures run through mouse events rather than touch, `accessibility-*` properties are ignored, and animations go through the web runtime instead of the native one. Anything you intend to ship on a phone needs checking on a phone, and the fastest way to get there is a QR code.

## Lynx Go

Lynx Go is a host application that embeds the Lynx runtime and loads a bundle from a URL, which means you can run your app on a real device without building anything native yourself. It is published as [Lynx Go — Dev Explorer](https://apps.apple.com/us/app/lynx-go-dev-explorer/id6743227790) on the App Store and [on Google Play](https://play.google.com/store/apps/details?id=com.funcs.io.lynx.go), and it scans the QR code that your dev server prints.

The Lynx team also publishes LynxExplorer builds from the [lynx-family/lynx](https://github.com/lynx-family/lynx) releases page. Both do the same job, though Lynx Go is easier to get onto a device because it comes from the stores rather than a sideloaded `.ipa`.

## Wiring up the QR code

The `@lynx-js/qrcode-rsbuild-plugin` package prints a scannable code whenever `rspeedy dev` starts. Add it to your Lynx config alongside the Vue plugin:

```ts [lynx.config.ts]
import { defineConfig } from '@lynx-js/rspeedy'
import { pluginQRCode } from '@lynx-js/qrcode-rsbuild-plugin'
import { pluginVueLynx } from 'vue-lynx/plugin'

export default defineConfig({
  environments: {
    lynx: {},
    web: {},
  },
  source: {
    entry: { main: './src/index.ts' },
  },
  plugins: [
    pluginQRCode({
      schema(url) {
        return `${url}?fullscreen=true`
      },
    }),
    pluginVueLynx({
      includeWorkletPackages: [/@vyui\//],
    }),
  ],
})
```

Declaring both environments matters more than it looks. The `lynx` environment emits `main.lynx.bundle`, which is what the QR code points at and what Lynx Go loads, while `web` emits `main.web.bundle` for the browser preview. Dropping `web` costs you the browser shell, and dropping `lynx` leaves the QR code pointing at nothing.

Run `pnpm dev`, scan the code, and the app opens, with saves reloading it in place. The [dev server guide](/guides/rspeedy-dev-server) covers the terminal shortcuts that cycle the code between entries and URL schemas.

## Three things that break before anything renders

Vy UI components depend on build configuration that the browser preview is more forgiving about than the native runtime, so a first device run tends to fail in one of three recognisable ways.

**Gestures crash the main thread.** Dragging a `VySortable` or a `VySwipeAction` throws `TypeError: cannot read property 'bind' of undefined`. The cause is that vue-lynx's main-thread loader skips `node_modules` unless you allowlist the package, so worklets shipped inside `@vyui/core` never register. The `includeWorkletPackages` entry above fixes it, and `npx @vyui/cli check` audits for it if you would rather not diagnose it live.

**Components render as unstyled boxes.** Tailwind rebuilds its `content` list from the bundled module graph, and the common configuration excludes all of `node_modules`, which drops every class string inside `@vyui/kit`. Let the Vy UI packages through the exclusion:

```ts [lynx.config.ts]
pluginTailwindCSS({
  config: 'tailwind.config.ts',
  exclude: [/[\\/]node_modules[\\/](?!.*@vyui)/],
})
```

**Colors collapse to white and black.** Lynx's native CSS engine resolves a single level of `var()` indirection, so a semantic token pointing at another token evaluates to nothing on device while working fine in the browser. Turning on CSS inheritance and inline variables is what makes the `--ui-*` token layer resolve natively:

```ts [lynx.config.ts]
pluginVueLynx({
  enableCSSInheritance: true,
  enableCSSInlineVariables: true,
  includeWorkletPackages: [/@vyui\//],
})
```

## Fonts

Custom fonts loaded with `url(...)` do not work in a native bundle. Rspeedy rewrites the reference to `webpack:///static/font/…`, and native Lynx cannot fetch that scheme, so the text silently falls back to a system face.

Two options work. Inlining the font as a data URI keeps everything inside the bundle and needs one config change:

```ts [lynx.config.ts]
output: {
  dataUriLimit: {
    font: Number.MAX_SAFE_INTEGER,
  },
}
```

The alternative is registering the font in a host application and referencing it with `local("Family Name")` from your CSS, which produces a smaller bundle but rules out Lynx Go, since you cannot add resources to an app you did not build.

## Reaching a local API

Lynx Go loads your bundle over the network, so `localhost` inside that bundle refers to the phone rather than to your Mac. Native bundles also have no `location` global, which means the code cannot infer the dev machine's address the way a browser page can.

Inlining the LAN IP at build time is the least painful fix:

```ts [lynx.config.ts]
import { networkInterfaces } from 'node:os'

function lanHost(): string {
  for (const nets of Object.values(networkInterfaces())) {
    for (const net of nets ?? []) {
      if (net.family === 'IPv4' && !net.internal) return net.address
    }
  }
  return 'localhost'
}

export default defineConfig({
  source: {
    define: {
      'import.meta.env.PUBLIC_DEV_LAN_HOST': JSON.stringify(lanHost()),
    },
  },
})
```

Your API client then reads `import.meta.env.PUBLIC_DEV_LAN_HOST` instead of assuming `localhost`. Changing networks means restarting the dev server, because the value is baked in at build time.

## Where Lynx Go runs out

Lynx Go is a fixed application, so it contains exactly the native modules its authors compiled into it. Anything that needs a native module they did not include cannot run there at all, and that covers most of the interesting cases: camera capture, biometrics, push notifications, secure keychain storage, and any third-party SDK.

The same limitation applies to native configuration. Font registration through `UIAppFonts`, permission strings in `Info.plist`, URL scheme handling, and app-level entitlements all live in a host application you control.

Once you hit any of those, the next step is building that host, which the [Xcode guide](/guides/testing-with-xcode) walks through end to end.

::callout{icon="i-lucide-info"}
Lynx Go remains the right tool for layout, styling, animation, gesture feel, and anything else that only needs the runtime. Keep using it for the fast loop and reach for a custom host only when a native module forces it.
::
