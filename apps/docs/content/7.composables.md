Vy UI exports composables from two packages. `@vyui/kit` has a handful of app-facing helpers you'll reach for directly. `@vyui/core` has those plus a set of primitive-authoring utilities that mirror Radix Vue / Reka UI's own exports — most app code never touches these directly.

## App composables

From `@vyui/kit`.

### useAppConfig

Injects the merged `AppConfig` provided by `VyUI.install()` / `provideVyUI()` — the same object you pass as `app.use(VyUI, { ui: {...} })`.

```ts
import { useAppConfig } from '@vyui/kit'

const appConfig = useAppConfig()
appConfig.ui.primary // 'green'
```

Falls back to a sane default (green primary, slate gray, the default icon registry) when rendered outside a `VyUI` context — tests, isolated stories — so anything reading it, like `useComponentIcons`, doesn't crash. Reach for it in app code that wants to read the active theme config reactively, e.g. to pick a color or icon at runtime.

### useColorMode

The reactive `{ mode, isDark, setMode, toggle }` singleton that drives dark mode across the app. Full writeup, including the app-root class + remount contract, lives on [Theming → Dark mode](/theming#dark-mode).

### useComponentIcons

```ts
import { useComponentIcons } from '@vyui/kit'

const { isLeading, isTrailing, leadingIconName, trailingIconName } = useComponentIcons(props)
```

This is what powers the `icon` / `leadingIcon` / `trailingIcon` / `loading` prop convention you see across kit components like `Input` and `Button` — `icon` routes leading unless `trailing` is set, `loading` takes precedence and swaps in `appConfig.ui.icons.loading`. Most app authors won't call this directly; it's mainly useful if you're building your own component that wants the same icon-prop ergonomics as the kit.

### useTray

Imperative `{ setView, goBack, close, ... }` access to an ancestor `VyTray` from anywhere inside it — handy for custom triggers or deep view bodies that shouldn't thread callbacks through props. See [Tray → useTray](/components/tray#usetray).

## Internationalization

From `@vyui/core`. Full story — what's a stopgap, what's still planned, the PrimJS `Intl` gaps they work around — is on the [i18n](/i18n) page; short version:

- `installIntlPolyfill()` — fills broken or missing `Intl.DateTimeFormat` / `Intl.NumberFormat` / `Intl.Collator` / `Intl.Locale` on native Lynx.
- `useDateFormatter()` / `DateFormatter` — date formatting that avoids the host formatter when it isn't safe to use.
- `useLocale()` — the active `locale` from `ConfigProvider`.
- `useDirection()` — the active `dir` (`ltr` / `rtl`) from `ConfigProvider`.

## Building custom primitives

::callout{icon="i-lucide-flask-conical"}
Advanced. These are for authoring your **own** headless component on top of [`@vyui/core`](/packages/core), not for typical app-building with `Vy*` components — skip this section unless you're building a primitive.
::

`@vyui/core` positions itself as a headless-primitive library, Radix Vue / Reka UI style, and these composables are the same-shaped building blocks that lineage exports.

### useId

```ts
import { useId } from '@vyui/core'

const id = useId() // 'vy-1'
const forced = useId(props.id) // pass a deterministic id to skip generation
```

Generates a stable unique id for `id` / `for` / `aria-*` wiring, preferring Vue 3.5+'s built-in `useId()` and falling back to an internal counter on older Vue. Pass `deterministicId` to force a specific value instead of generating one.

### useFilter

```ts
import { useFilter } from '@vyui/core'

const { startsWith, endsWith, contains } = useFilter()
startsWith('hello', 'he') // true
endsWith('hello', 'lo') // true
contains('hello', 'ell') // true
```

String-matching helpers for search/filter behavior (e.g. Combobox-style filtering). Prefers `Intl.Collator` for Unicode-aware comparison, falling back to plain case-insensitive comparison when `Intl.Collator` throws or isn't usable — the same PrimJS-safety pattern as the i18n composables.

### useForwardProps

```ts
import { useForwardProps } from '@vyui/core'

const forwarded = useForwardProps(props)
```

Returns a computed merging a component's default props, the props actually assigned by its parent, and the reactive `props` argument — the building block for a wrapper component that needs to forward only the props its parent explicitly set, not Vue's fully-defaulted prop object.

### useEmitAsProps

```ts
import { useEmitAsProps } from '@vyui/core'

const emitsAsProps = useEmitAsProps(emit)
```

Converts a component's `emit` function into an object of `onXxx` handler props. Vue has no built-in "forward my emits to a child" mechanism ([vuejs/core#5917](https://github.com/vuejs/core/issues/5917)), so this lets a wrapper spread both props and events onto an inner element transparently.

### useForwardPropsEmits

```ts
import { useForwardPropsEmits } from '@vyui/core'

const forwarded = useForwardPropsEmits(props, emit)
```

`useForwardProps(props)` merged with `useEmitAsProps(emit)` when an `emit` function is passed. This is the one most wrapper components actually call directly.

### useForwardExpose

Lets a wrapper component transparently forward `expose()`d methods/refs and props from an inner child up through itself, and returns a `forwardRef` function to attach to the inner element or component's `ref`. Returns `{ forwardRef, currentRef, currentElement }`. Used for `asChild`-style APIs — see [`@vyui/core`](/packages/core) for the `Primitive` / `Slot` / `asChild` pattern this supports.

### useStateMachine

```ts
import { useStateMachine } from '@vyui/core'

const { state, dispatch } = useStateMachine('closed', {
  closed: { open: 'open' },
  open: { close: 'closed' },
})

dispatch('open') // state.value === 'open'
```

A tiny typed finite-state-machine helper — `machine` maps each state to the events it accepts and the state each event transitions to. `dispatch(event)` only transitions if the current state has that event defined, otherwise it's a no-op. Used internally by primitives with open/closed/checked-style state.

### usePrimitiveElement

```ts
import { usePrimitiveElement } from '@vyui/core'

const { primitiveElement, currentElement } = usePrimitiveElement()
```

Resolves a template ref — which may be a component instance or a raw element, since Lynx's `<view>` / `<text>` aren't DOM elements — down to a stable `ElementHandle`, the thing every `@vyui/core` primitive uses internally to get "the actual rendered element" regardless of whether `asChild` merged it into something else.

::callout{icon="i-lucide-info"}
`@vyui/core` has more composables under the hood powering its own gesture, animation, and focus internals. They aren't part of the public API surface and aren't documented here.
::
